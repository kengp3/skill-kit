PROJECT-LOCAL · MODEL-LED WORKFLOW

從本地設定到
可驗收的任務成果

統一專案設定，讓模型負責判讀與推進；hooks 觸發流程要求，無法使用時自動接手。

0.3.0 來源設計實際能力以證據判定核心無必要 runtime script
01

模型主導，保留可驗證的任務進度

0.3.0：統一設定、移除必要腳本依賴、支援模型分工。

task-harness 是由模型執行的任務流程。主責 agent 保存唯一任務合約，核對授權、成果與證據，在原授權內繼續必要工作。安裝技能與設定 hooks 不會啟用所有任務。

PROJECT SETTINGSproject-setting.md 保存專案長期設定
TASK CONTRACT同一任務的狀態、覆寫與恢復資訊
MODEL-LED CHECKShooks 觸發或主責模型主動核對
核心不需要 Python、Node.js、外部 CLI、MCP 服務或 runtime script。個別任務所需的真實操作與測試仍須取得證據；模型判斷不能冒充未執行的測試。
02

哪些設定只做一次？

專案長期設定、任務指定與宿主能力分開管理。

範圍何時處理保存位置
本地 skills首次安裝或明確升級專案 .agents/skills/；保留各技能 references 與 assets
專案設定初始化、明確更新或移轉／修復根目錄 project-setting.md
本次模型指定本次任務；恢復同一任務仍有效原任務合約，新任務不自動沿用
宿主載入／信任／事件依實際版本與設定變更查核實際診斷與事件證據，不直接沿用舊資格
03

取得來源或完整候選

使用者不必先建包。維護者工具與日常流程分開。

取得本版來源或經確認的完整候選。完整 harness 包含四個技能、各自 references／assets、固定 hooks 與內容指紋；技能 scripts 是選配輔助。版本 0.3.0 不再把舊 Python hook handler 納入封裝。

維護者選用：只建包與核對，不安裝
python3 -B scripts/package_harness.py dist/candidates/kengp3-harness-0.3.0
python3 -B scripts/package_harness.py --verify dist/candidates/kengp3-harness-0.3.0

目的地必須不存在；保留舊候選，建包不會刷新 marketplace、已安裝快取或其他專案。原有 dist/kengp3-harness 可能仍是舊版，不可只看目錄名稱判斷實際載入版本。

04

在專案內本地安裝

可使用檔案管理員複製；不要求安裝第三方 Skills CLI。

  1. 確認要採用的專案根目錄與來源版本。
  2. 單獨使用文件規範時，只把 project-setting 目錄複製到專案 .agents/skills/。
  3. 完整使用時，一起複製 task-harness、project-setting、define-task、ai-code-review。不要只複製 SKILL.md。
  4. 已有同名技能先核對並保留舊版，依明確升級意圖替換，不覆寫未確認的自訂內容。
  5. 重開專案工作階段，核對技能實際載入，再初始化專案設定。

使用 native plugin 時，先選定版本與安裝範圍，再依宿主支援的本機 marketplace 流程處理。plugin cache 與專案 skills 不是同一安裝來源；避免同時載入兩份相同技能或 hooks。

既有 npx skills add/list/remove 為選用第三方安裝方式，具有自身 Node.js 需求，且遠端版本可能落後本地來源；不作核心前置條件。

05

由 project-setting 依規格設定

project-setting 可獨立使用；task-harness 提供自己的設定規格。

只設定文件規範
使用 $project-setting 初始化這個專案的文件規範。
指定包含 task-harness
使用 $project-setting，包含 $task-harness，依它提供的 Markdown 設定規格初始化這個專案；保留其他設定。

project-setting 只執行通用設定操作。task-harness 自行提供欄位、格式、有效性、移轉與修復規則，完成後由 task-harness 重新讀回檢查。單獨使用 project-setting 不加入 harness 專用設定或 hooks。

合併到現有文件分類表的兩列；既有位置優先
| task-contract | 任務合約與可恢復狀態 | docs/plans/{slug}.task-contract.md |
| hook-receipt | 實際 hook 事件的技術收據 | docs/research/{slug}.hook-receipt.md |
Task Harness 區段的最小設定
## Task Harness

| 設定項目 | 值 |
| --- | --- |
| schema_version | 1 |

文件分類表是合約與收據位置的唯一來源，不再增加 contract_dir、receipt_dir 或另一份 JSON。允許表格列順序與空白調整；缺漏、重複或無效欄位依規格處理，不自行猜值。不要為初始化預建空目錄或假收據。

06

明確啟用任務與模型分工

主責保留對話模型，其他模型使用宿主原生 agent 能力。

開始執行
使用 $task-harness 完成這項任務：修正空輸入行為，保留既有 API，並完成適用回歸驗證。

主責先核對需求、設定與授權，保存合約後推進。規劃、執行、驗證、審查是四個預設階段，也可自訂；不強制每個任務走完全部階段，不預綁模型。

設定項目意義
model.default專案預設候選清單
model.stage.<完整階段名稱>該階段的候選清單
model.role.<完整角色名稱>該 agent 角色的候選清單
清單語法示意；模型名稱須換成可用識別字
[模型A;high, 模型B;medium]
[模型A;high, 模型B]

由左至右嘗試，分號連接模型與強度。優先序是本次明確指定、任務、角色、階段、專案預設；皆未設定才繼承主責。清單耗盡自動回退專案預設，沒有專案預設才沿用主責，不必填 default，同模型不重複嘗試。

強度不支援時優先保留模型並用宿主預設；明確禁止變更時遵守限制。手動切換對話模型只影響後續真正繼承主責的派工，已啟動 agent 不重啟或改派。需要獨立審查而無法派工時，主責可接手其他工作，獨立條件保留未完成。

07

唯一任務合約

合約保存任務狀態，設定檔保存長期規則，收據保存實際事件。

沿用同一份合約及既有穩定成果 ID，保存目標、範圍、驗收、依賴、當前授權與恢復資訊。主責是唯一語意寫入者；worker 或 hook 不另建第二份進度權威。

重要成果、交接與正常收尾保存後實際讀回。保存失敗或結果不明時先核對原合約，暫停真正依賴該更新的操作，不另建替代合約或重做產品修改。

本次模型覆寫與實際執行者記入原合約，同任務恢復仍有效；只有明確要求設為專案預設才更新 project-setting.md。宿主模型、強度或身分不可觀測時標未知，不能編造值。

完整合約範本與恢復規則、模型紀錄與回退規則。

08

共同檢查時點與完成條件

hooks 觸發與主責主動檢查共用同一規則。

檢查時點必須核對
開始或恢復專案設定、授權、進度與下一步
派工或切換階段前前置條件、負責 agent 與模型
agent 回報後成果、直接證據與任務狀態
準備結束前所有必要完成條件；仍有可執行的必要工作就繼續

只有所有必要成果與適用驗收有目前證據，才能宣告整體完成。取消、worker 宣稱、設定寫入或 hook 命令成功都不是產品通過。其他可做工作繼續，真實缺口保持未完成。

09

恢復同一任務，安全升級設定

先對帳已發生的結果，再決定下一步。

跨對話續作
使用 $task-harness 接續這份任務合約：<已確認的原合約路徑>。

先核對實際產物、原執行者與未知操作，再保存接手資訊。逾時或斷線不代表操作沒發生；已完成操作不重做，已有 agent 不重派，只有成果或條件改變才重驗相關部分。

舊 harness-project.json 的一次性移轉

  1. 先提示將移轉，讀取新舊資料及既有產物。
  2. 由 project-setting 依 task-harness 規格合併到 Markdown，沿用既有位置。
  3. 核對新設定寫入且逐項對帳無遺漏。
  4. 通過格式與內容驗證，確認目標版本支援且正常流程實際讀回。
  5. 三項門檻全過後才刪除舊設定，不留備份。失敗或衝突保留原檔並回報。

舊 host 資格只作歷史紀錄，新能力另依實際診斷判定；不把環境驗證加成刪檔門檻。合約、收據與其他成果不隨移轉搬移或刪除。

10

固定提醒與自動接手

標準接入不需要外部 handler；模型負責內容判讀。

事件本版接線與邊界
SessionStart內建 echo 固定提醒：讀取確認根目錄的設定、恢復同一合約、核對現況。
UserPromptSubmit內建 echo 固定提醒：核對最新要求與四個共同檢查時點。
Stop固定輸出 {}，是合法的被動回應；不提供條件式阻擋或一次性補救。

接線不解析輸入、不掃描專案、不寫合約或設定、不產生新授權。Windows 使用 cmd 的內建 echo，原生 Windows 驗收須另行記錄。平台信任仍走正常流程；測試用的單次信任略過不等於已通過正常信任驗收。

hooks 缺失或失效時先診斷並嘗試修復。仍無法使用，由主責模型自動接手四個時點，沿用同一份合約與驗收標準。恢復後自動銜接，不重複派工或操作。主動檢查不等於宿主機械攔截。

此區只展示模型流程，不連接本機 harness。無 JavaScript 時可直接依上方表格與共同檢查規則閱讀。

11

停止、取消與停用

接手流程不擴大原授權。

  • 使用者 Stop 結束執行，不為補寫紀錄而抵抗停止；明確續作後才核對恢復。
  • 取消保留依據與已有成果，不當成驗收成功。
  • 停用只處理指定專案與可辨識來源；保留其他 hooks、設定、合約及證據。
  • 複製式本地安裝可移除該專案所採用的技能目錄；移除技能與停用專案 hooks 是兩個動作。
  • native plugin 依其安裝來源及宿主正常移除流程處理，之後重新載入查核，不全域關閉其他功能。
12

一個完整的小任務

以實際產物證明每一步，不把流程描述當驗收。

1

明確啟用與設定

要求 task-harness 產出指定成果。主責確認根目錄，缺設定時委派 project-setting，完成後讀回。

2

保存與推進

建立唯一合約並核對授權，按模型規則派工或由主責完成小任務。hooks 不可用則主動檢查。

3

驗收與收尾

讀回成果並執行必要檢查。核對所有條件，記錄執行者、證據與限制，保存讀回合約後交付。

若中途有 append 回覆遺失，先讀取 ledger／原操作結果；已寫入就不再 append。不能只因 hook 恢復或對話切換就重做副作用。

13

各元件的實作責任

內容規格與設定操作分離。

元件責任
task-harness定義自身 Markdown 格式、有效性、移轉與模型流程；判讀任務與驗收。
project-setting依提供的規格執行設定，檢查寫入邊界、保留無關內容並讀回。
hooks.json固定內建命令傳遞提醒，Stop 為被動空物件。
主責模型維護同一合約、派工、四時點檢查、恢復與完成判斷。
選配 scripts輔助證據或自動化，缺失不阻擋核心；不能猜測無法核對的值。
維護者測試／建包工具開發與驗收使用，不成為使用者的 runtime 需求。

舊 Python handler 來源與測試保留作歷史開發對照，不是新包入口。內容指紋仍沿用 runtime-manifest.json 的既有名稱；名稱不代表需要額外 runtime。

14

問題排查與能力回報

只暫停真正依賴缺失操作的工作。

問題處理方式
設定缺漏／重複／無效依 task-harness 規格交給 project-setting；衝突先回報，不猜值。
hooks 未載入或未信任診斷精確來源與宿主流程；仍不可用就由模型接手，不宣稱已機械攔截。
指定模型不可用依候選順序及自動預設回退，不循環重試；全部不可用只暫停受影響工作。
強度不支援保留模型並使用宿主預設；明確強度限制仍遵守。
無法建立子 agent診斷後由主責接手，明確獨立審查條件保留未完成。
工具結果不明查原結果、產物與實際副作用後再決定，不盲目重派或重播。
模型／宿主身分不可取得保存未知與原因，不編造 ID 或把設定值當實際結果。
