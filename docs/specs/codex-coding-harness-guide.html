01

先理解：你啟用的是一個任務流程

原生工具執行工作；skill 主導任務；hooks 補上恢復、授權核對與正常收尾提醒。

0.2.1 的核心是一份由 agent 維護的任務合約。它讓未完成成果、最新授權及恢復資訊能跨回合保存。你說明目標與限制後，agent 負責建立、讀回及更新；不用你手動填進度表。

任務連續性

必要成果全部對帳

局部完成仍保留未完成工作；完成判準包含相稱驗證與必要整合。

可恢復

同一合約接續

換對話後核對原執行者與實際產物，再保存新主責，不複製成第二份合約。

任務級啟用

一次啟用涵蓋同一任務

後續回合及明確續作沿用；新任務、其他專案不自動繼承。

「非侵入式」代表產品流程不必改成自製執行器，也不必手動記帳。完整接入仍會有 plugin、專案設定、任務合約與必要收據；不等於零檔案、零安裝足跡。
02

一次性設定與日常操作

先接好環境，日常只提供任務與必要決策。

頻率你或 agent 做什麼完成後留下什麼
每個使用環境一次核對 Python、安裝完整候選、正常信任 hooks；確認實際載入版本。原生 plugin 安裝與信任紀錄。
每個專案一次在授權專案建立 harness-project.json、合約目錄，核定宿主資格。專案設定；目錄位置遵守該專案規範。
每個新任務一次明確使用 $task-harness，給目標、可寫範圍與驗收。由 agent 建立唯一任務合約。
同一任務的後續回合說明最新要求；不用重新安裝或建立新合約。agent 更新當前授權與必要狀態。
跨對話／session 時給同一份合約路徑，明確要求接續。核對停止與成果後保存接手。
版本／協定／相關設定改變時按影響重新核對載入、信任與資格；可重用仍等效的證據。更新來源與驗證依據；不是每次任務重跑全套。

03

準備：確認拿到完整的 0.2.1

本手冊核對日期為 2026-10-25；舊名 Personal Harness 的已驗入口是 Codex CLI／app-server 0.164.0。

必要環境

  • 可使用的 Codex 本機執行入口與既有登入。
  • 執行環境能找到 python3；使用標準函式庫。
  • 原生支援並允許三個 hooks，來源能正常信任。
  • 已確認專案根目錄、可寫範圍與文件規範。

版本界線

Python 3.10+ 是相容目標；直接執行驗證使用 Python 3.15。Windows 命令雖有封裝，未做 Windows 原生資格驗收。

不同入口先看實際載入來源與事件能力。相同核心／協定可重用證據，不因視窗不同自動重做全套。

04

安裝完整套件：固定來源，再交給原生 plugin 管理

這一節是供日後採用的操作教學；本次製作手冊沒有執行安裝。

安裝影響：舊名 personal-harness 已驗 plugin install 的 scope 是 user，會寫入所用 Codex state／快取。專案本機 marketplace 不等於「完全 project-only 安裝」。若目前仍禁止使用者層變更，先停在候選驗包；有明確採用授權後才執行下面步驟。

  1. 固定到 0.2.1 的實體目錄

    本 repo 既有 .agents/plugins/marketplace.json 指向 ./dist/kengp3-harness，改名後提供同源 0.2.1 離線包；採用前仍須驗包。以下另建固定版本 catalog 的範例保留已凍結候選，不會遷移既有安裝。

用 Python 3 執行；先替換兩個絕對路徑
from pathlib import Path

    以下命令來自本機 0.164.0 --help 與官方文件；它們是將來的安裝操作，不是本手冊執行結果。

安裝時會寫入所用 Codex 使用者層 state／cache

codex plugin add kengp3-harness@kengp3-harness-021 --json

只把 installedPath 換成實際回傳值

  1. 正常信任三個精確 hook 定義

    在同一使用環境開啟 Codex CLI，使用 /hooks 檢視來源、命令、版本與 timeout，逐一信任 SessionStart、UserPromptSubmit、Stop。新安裝或來源改變時可能需重審。不要手填 trust hash 或繞過審查。

  2. 以新的 session 確認載入

    核對版本 0.2.1、四個 skills 與三個 hooks，確認 hooks enabled／trusted 且沒有載入錯誤。plugin 已安裝、hook 已信任、handler 實際能執行，是三個不同查核。

安裝一次後不必每個任務重裝。不要再把同一 handler 複製到 project hooks，否則 plugin 與 project 來源可能重複執行。原生快取由 plugin 管理，不直接修改快取中的腳本。

05

每個專案接入一次

設定負責「這個專案採用 harness」；任務合約負責「這個任務目前是什麼」。

先建立什麼

在確認根目錄保存 harness-project.json。project_root 必須是設定所在的實際絕對路徑。

合約目錄要先存在；收據目錄可由 hook 在首次必要補救時建立。兩者在專案內且不能互相包含。

接入不等於任務授權

設定存在不代表可以開始修改程式；必須收到明確任務啟用與有效授權。

在其他未接入專案沒有產品任務介入；handler 的發現範圍仍受最近設定與 Git 邊界限制。

harness-project.json：初始模板，不可直接當資格已驗證
{
  "schema_version": 1,
  "project_root": "/absolute/project",
  "contract_dir": "docs/plans/harness",
  "receipt_dir": "docs/research/harness-hook-receipts",
  "host": {
    "session_identity": false,
    "user_turn_identity": false,
    "stop_continuation": false
  }
}
路徑為示意，依目標專案規範調整
your-project/
├── harness-project.json
├── docs/plans/harness/                 # 必須先存在；直屬 *.md 合約
│   └── fix-parser.md                   # agent 於啟用任務時建立
└── docs/research/harness-hook-receipts/ # 首次必要補救才可能建立

三個 host 資格如何核定？

資格必須有什麼依據不能拿什麼代替
session_identity真實 SessionStart 等事件可歸屬到可靠 session。手造一個 session ID。
user_turn_identity真實使用者回合與 hook 續作的身分可對帳。每次收到事件就當成新授權。
stop_continuation正常 Stop 能在同一工作回合做一次有界續作。設定存在、CLI 合成 payload 或一次 exit 0。
初始模板全部為 false 是未完成接入狀態。agent 應先核對舊名 personal-harness 在 0.164.0／0.2.1 的證據是否與實際核心、協定及相關設定等效；新 plugin 身分的安裝、載入與信任須另行核對，可證明等效的其他行為證據才可重用，否則保留缺口。不要求每個新任務重做資格測試，也不能為消除警告直接翻 true。

需要專案層明確控制 plugin 時

以下合併進目標專案已信任的 .codex/config.toml；若已有相同表就更新欄位，不重複宣告。這是未來專案接入設定，本次手冊未寫入。

此 key 必須與實際 marketplace 名稱完全一致
[plugins."kengp3-harness@kengp3-harness-021"]
enabled = true

如果所用環境明確關閉 hooks，須先診斷。只有採用授權涵蓋時才在所需設定層合併 [features]／hooks = true；組織強制設定不能靠專案設定繞過。

交給 agent 的專案接入指示
只在目前這個已確認的專案接入 kengp3-harness 0.2.1。
先讀取專案規範並確認根目錄，保留既有未提交工作。
確認完整 plugin 與三個 hooks 已載入；不要重新安裝或修改全域設定。
依專案規範建立 harness-project.json 與合約目錄，收據目錄留在專案內。
宿主資格先依實際版本、協定與已有驗證證據核定；無依據維持 false 並說明缺口。
若需要新增行為驗證，先說明最小必要範圍，不自行啟動 trial。
完成接入讀回後停止，先不開始產品修改。

官方對本機 marketplace 的專案啟停說明：Enable or disable a plugin for a repo。

06

每個新任務：明確啟用一次

最有用的輸入是目標、限制及驗收，不是更長的流程口令。

一般 bug 任務範本
使用 $task-harness 完成這個 bug 修復。
目標：空輸入回傳空集合，既有有效輸入維持原行為。
範圍：parser 模組及必要測試；不要改公開 API、全域設定或其他專案。
驗收：空輸入、正常輸入與錯誤輸入都符合既有契約。
請先建立並讀回唯一任務合約，在原授權內持續完成所有必要成果及驗證。
真的受阻時保存缺口與下一步，不把未完成驗收改成後續建議。

小任務也能簡單

小修改範本
使用 $task-harness 將 greet(name) 的招呼由 Hello 改成 Hi。
保留名稱與標點；以 greet("Ada") == "Hi, Ada!" 驗收。
一個完整成果包含修改與直接檢查，不需額外拆分或委派。

只討論也要明確

討論範本
使用 $task-harness 先討論解析器調整方案。
本回合只讀取、分析與維護任務約定，不修改產品或執行 trial。
提出取捨後等待我的決定。

啟用後，agent 應自行完成

  1. 核對最新要求、現況、既有修改、必要 hooks 與可用檢查。
  2. 建立或沿用唯一合約，保存且讀回成功，再做相依產品操作。
  3. 依依賴推進可做的必要成果，按風險選驗證；有新診斷進展時自主修復。
  4. 全部必要成果與適用整合檢查通過，才把整體設成 done。
這個 skill 的 allow_implicit_invocation 是 false。請明確選取／提及 $task-harness；同名技能有多個來源時，核對它來自 kengp3-harness 0.2.1。不要只說「繼續」卻讓新對話猜是哪一份任務。
07

任務合約：一份可讀、可恢復的權威內容

Markdown 放解釋，固定標記內的一個 JSON 區塊提供機械欄位。

內容用途維護者
task_id / objective / scope辨識任務、目標與授權範圍。主責 agent；不依檔名猜任務。
requirements必要成果、穩定 ID、依賴、驗收證據。主責 agent；小任務可只有 T1。
owner_session_id目前主責身分；null 表示未綁定。agent 從可靠原生資訊取得；不虛構。
authorization當前 user-turn、execute/discuss/wait/stop 與依據。agent 核對最新要求後保存；hook 不猜。
recovery下一步、具體阻礙、結果不明操作、取消依據。agent 在重要轉換保存與讀回。
展開完整可複製模板（不是已授權的工作合約）
由 agent 代入實際專案、身分與約定；使用者不必手填

## 約定與驗收依據
說明需求來源與具體預期，不另維護一份狀態表。
固定標記間必須恰好一個 json code block；重複 key、多區塊、錯誤歸屬或循環依賴會被拒絕。evidence 字串存在仍不代表產品正確，agent 必須讀取並核對。

重要狀態轉換、接手與正常收尾時保存；不用每次讀檔都記帳。一次保存可以同時記錄前置驗收與交接資訊。保存失敗或結果不明，先核對同一文件，成功前暫停相依操作。

08

任務如何推進與完成

狀態只有五種；授權、程序存活與操作結果分開記錄。

維度可用內容不可混淆
整體與成果狀態pending、in_progress、blocked、done、cancelledin_progress 不證明程序還活著。
本回合有效授權execute、discuss、wait、stop未完成不代表允許現在實作。
操作結果如 unknown_operations 的待查證紀錄結果不明不等於失敗，不直接重做。
驗收依據產物、檢查、版本／指紋工具 exit 0、回合結束、agent 自述都不能單獨證明完成。

驗證如何選

先建立具體行為與判準，再按影響範圍決定測試。小修改做直接檢查；共用介面、權限或生命週期風險要有消費者／整合覆蓋，必要時獨立 review。沒有例行人工核准點，也不保證永遠不用提問。

09

跨對話續作：給原合約，不重開任務

續作先核對現況，再接上未完成工作。

新對話貼上完整合約路徑
使用 $task-harness 接續這份任務合約：
/absolute/project/docs/plans/harness/fix-parser.md
請先核對最新要求、原執行者停止狀態與現有產物。
結果不明先查證；保留仍有效的成果，只重驗受影響部分。
成功保存新的主責與本回合授權後，再完成所有必要缺口。
沿用同一任務與合約，不建立替代權威狀態。

找不到合約時

先用已知路徑；必要時只在已確認專案內尋找並核對內容。有多個候選或歧義才詢問，不掃全機或建立全域索引。

同一對話切換任務

先保存原任務交接資訊並解除原 owner_session_id 綁定，再切換。不要取消或複製原任務；新任務另行核對授權。

中斷可能發生在保存途中。從最近成功保存的合約核對產物，不假設「最後一次寫入」一定完成。單一主責是協作協議，0.2.1 沒有跨程序原子鎖。

三個 hooks 如何介入

必要 hooks 是能力補強；主責 agent 仍負責判斷、保存與驗收。

事件提供什麼不做什麼
SessionStart目前 session 身分、有效綁定或條件式接手提醒。不自動接手，不把 compact/resume/fork 當新授權。
UserPromptSubmit原生 user-turn 身分，提醒核對最新要求與有效授權。不靠關鍵字猜權限，不改合約、不重置補救額度。
Stop符合資格、當前綁定與授權時，正常收尾最多一次提醒。不阻止使用者 Stop、不背景重啟，不保證任務完成。

點選情境，看正常 Stop 的判斷

下列為教學情境。輸出已在可丟棄目錄以實際 handler 離線核對；不是新的真實 agent trial。

完整文字規則：有效 execute 與必要缺口才可能提醒；discuss/wait/stop、blocked/cancelled、已補救或一致 done 不再要求實作。unknown 只要求查證。

展開 Stop handler 的判斷順序
  1. 驗事件；若 stop_hook_active=true，直接不再延續。
  2. 找專案設定，核對路徑、必要宿主資格與所有已標記合約。
  3. 選目前 session 的唯一有效合約；沒有綁定就不介入。
  4. 核對當前 turn 等於合約授權 turn；過期／不符時明示缺口。
  5. discuss/wait/stop、blocked/cancelled 或一致 done 放行。
  6. 若需要補救，先 exclusive-create 技術收據；已存在就不再發送。
  7. unknown 只提醒查證；否則提醒完成原授權內必要成果或保存具體阻礙。
收據 key 取自 [session_id, user_turn_id] 的 SHA-256；收據內才附 task_id 與合約指紋。同一工作回合切換 task_id 不會得到第二次補救。部分或空收據也保留，不以刪除收據爭取重試。

完整實例：從 bug 修復到中斷接手

以下保留舊名 personal-harness 的實測案例，說明日常流程；不是改名後的新 trial。

1

一次啟用

使用者要求修復事件 started／completed 類型衝突；正常、衝突、逆序三種行為都是必要驗收。

2

先保存約定

agent 建立唯一合約：T1 正常基線、T2 衝突修復、T3 逆序與整合。完成 T1 後保存直接證據，T2／T3 保留 pending。

3

發生中斷

V3 驗收使用受控前景時窗與原生 interrupt；日常使用者可直接 Stop，不需要建立等待程式或控制 driver。

4

新對話明確接續

給原合約路徑。新主責先確認舊執行者停止、T1 及產物仍有效，保存新的 owner／turn 後才修復。

5

整合後才完成

保留原基線；因共用 summarizer 改動影響正常路徑，仍需重驗。正常、衝突、逆序全部符合契約後，更新同一合約為 done。

實際 V3 補驗：兩個 sessions／兩次輸入，約 242 秒，維護者 checker 3/3。第一段曾出現合約重複 JSON，agent 在同回合修復並成功讀回後才進中斷。這是一次固定案例的實測，不是普遍成功率或自動取消保證。

日常小修改則可只有一個 T1：像 Hello → Hi 與一項直接檢查。不用複製 V3 測試流程，也不用每次跑七個驗收案例。

實作拆解：日常元件與開發工具的邊界

共用核心保持小：一個合約協議、一個 Python handler、一組原生 plugin 接線。

位置／函式實作責任關鍵界線
skills/task-harness/SKILL.md主責、成果、授權、風險驗證、自主修復、交接及整體驗收。語意行為由 agent 執行，不是硬性完成保證。
agents/openai.yaml技能顯示與明確啟用 policy。allow_implicit_invocation=false。
hooks/hooks.json三事件指向同一 Python handler；每次 timeout 10 秒。不是產品任務的 10 秒預算。
load_config()由 cwd 向上找最近 harness-project.json，到 Git 邊界停止；也可明確指定。實際 root、目錄、symlink／特殊檔案與越界查核。
find_contracts()核對標記、JSON、schema、依賴、task ID 與 owner 衝突。只讀合約目錄直屬 *.md，最多 64 份。
select_contract()優先目前 session 的未結束合約，必要時核對當前 turn 的終態合約。不按最後修改時間猜選。
stop() / reserve_receipt()驗授權與缺口，先 O_EXCL 建收據並 fsync，再要求一次補救。收據保留；輸出遺失也不重送。
main()stdin JSON → stdout JSON；錯誤輸出簡短 systemMessage。不用 exit 2 製造延續；exit 0 不代表任務通過。
scripts/package_harness.py建完整套件與內容 manifest；驗包唯讀。不安裝、不覆寫既有 release。
task-harness/scripts/run_check.py可選的小型非互動檢查 receipt，記錄 argv、輸出、回傳碼與來源指紋。無 timeout／持久程序所有權；不是 grader 或 trial runner。

日常路徑

完整 plugin、三個 hooks、專案設定、唯一合約、正常專案測試；只有必要補救才會產生技術收據。

開發端才用

案例 fixture、grader、原生 RPC driver、證據快照與中斷取證。不放進使用者每次開發流程，也不要求使用者計時或監看。

讀取限制：event 1 MiB、每份合約 512 KiB、直屬 Markdown 最多 64 份。超限會明示缺口，不截斷後當成全部讀完。完成很久的合約若需要移出掃描目錄，由 agent 依專案規範保存可追溯位置，不隨意刪除。
