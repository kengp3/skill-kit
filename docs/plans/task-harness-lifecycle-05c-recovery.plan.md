# H05C：中斷恢復與未知結果核對

**What to build:** 真實 agent 在原生中斷後保留有效成果，由新 session 明確接手同一任務合約；操作結果不明時查證實際產物而不重播副作用。

**Blocked by:** H05A（真實接入與控制合格）；不依賴 H05B 的產品結果。

**Status:** pending

規格：[任務合約與必要 hooks](../specs/task-harness-lifecycle.spec.md)。案例及上限：[H05](task-harness-lifecycle-05-desktop.plan.md)。

- [ ] 固定 V3／V4 的可丟棄材料、首次工作與明確續作輸入、interrupt 觸發、必要 session／turn 上限與直接判準。
- [ ] V3 使用實際原生中斷，不以 stop 合約或合成事件冒充；核對終態及自有 writer 停止，再開新 session。
- [ ] 中斷本身不授權續作；控制端只發預先授權的續作要求。新主責核對原合約、現況、有效成果及最新限制，成功保存接手後才推進。
- [ ] 全程只有一份權威合約；只重驗受影響成果並完成最後整合驗證。最後一次未確認保存不被假定成功。
- [ ] V4 使用一次可辨識的測試 append 產物與未知回應預置；agent 先讀回，再保存判斷，append 次數不增加。
- [ ] 結果不明與停止未確認時不得重跑／接手；到期沿用原期限與既有控制，不另建監控或要求人工觀察。
- [ ] 保存中斷、終態、writer、接手順序、合約／產物前後證據；預置故障與真實中斷明確區分。

完成條件：V3、V4 各項直接證據皆成立。第一次自然完成導致未觸發中斷，不算中斷驗收成功，也不擅自重跑整次案例。H05 最終結案另需 H05B 完成；此票不宣稱全套通過。
