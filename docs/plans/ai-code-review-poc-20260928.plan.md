# Code review POC 與易讀性驗收

## Objective

以簡單至複雜的情境實際執行目前 `ai-code-review`，核對判斷、證據與報告易讀性；根據失敗項修改 skill，重驗至本輪門檻全部通過。

## Background

前輪已修正雜湊核對工具。本輪須另以 review 報告證明技能能找到問題並清楚交付修法，不能用工具測試或歷史報告代替。POC 的程式可被判為 Request changes／Hold；這與報告本身是否通過驗收分開。

## Materials

目前 skill 及 references、既有分頁與 Java partial-return fixture／runner、四組固定來源與契約、本輪實跑紀錄。審查者僅取得 skill、請求及原始案例；不提供本計畫的預期答案。

## Boundaries

保留既有變更與歷史證據。只修正本輪驗證支持的 skill 問題；不修改 fixture 來迴避缺陷、不編造外部整合結果、不安裝全域依賴、不自動 commit／push。中止或未完成的獨立驗證不得算通過。

## Assumptions

本輪驗收限定四個初始情境與一個修後新情境的報告品質，不構成 skill 對所有程式的查錯保證。使用 `skill-creator` 的獨立 forward-testing，由不同上下文的審查者產報告，再以原始來源和結果稽核。

## 情境與執行

| 情境 | 目的 | 預先固定的判斷基準 |
|---|---|---|
| S1 游標分頁 | 小 diff、兩個 caller | 1 個共同根因，重複資料與匯出失敗，Request changes |
| S2 折扣契約變更 | 正確的有意行為改變 | 新規格接受門檻等值，Approve，不因與舊版不同而誤報 |
| S3 部分退貨 | 多 class、邊界、拒絕、重試及副作用 | 4 個根因：第 30 天、分次退貨運費、退款拒絕前修改狀態、重播檢查順序；Request changes |
| S4 發布收據 | 正確來源但必要整合證據不足 | 缺 durable transport 驗證，Hold；不可捏造程式 bug 或宣稱整合通過 |
| S5 快取期限（修後 forward test） | 同拓樸 helper 抽取、兩 caller、空值與邊界 | 期限等值錯誤仍命中，共同根因一項；Request changes；空字串有效值不得另誤報 |

1. 固定原碼、契約、diff、案例及原始執行輸出；驗證建立的情境符合上表。
2. 獨立審查者依目前 skill 產生四份繁體中文報告與獨立雜湊索引。
3. 核對來源、實測與報告；用另一位讀者驗證是否能從首頁及問題總表理解結果與第一步。
4. 檢查實際渲染的可讀性、表格、圖與導覽；修正失敗項及對應最小 skill 指引。
5. 改動判斷流程時重跑受影響情境；只改報告表達時保留執行證據並重新產報告與稽核。用新情境做修後 forward test，確認改善可轉移。

## Definition of Done

- 四份初始情境與修後 S5 報告的決策、根因與缺口符合固定規格及實際結果；沒有漏掉已植入的阻擋或新增無根據阻擋。
- 每項問題可找到精確來源、輸入／預期／實際、影響、具體修法與解除條件；原碼和建議碼不混淆。
- 首頁與問題總表能回答「結果、剩餘事項、第一步」；清楚標示 scope、時間與限制；完整 SHA-256 僅在索引。
- 引用與 hash 有效、圖不誤導 caller／guard、五章與最後檔案清單完整；實際渲染沒有影響閱讀的裁切或溢出。
- 獨立稽核完成；所有必要失敗項有修正與重驗證據。最終摘要包含情境結果、優化前後差異、驗證與限制。
