# H05B：完整交付與授權遵循

**What to build:** 真實 agent 在一次啟用後持續交付所有必要成果、補齊驗收缺口，且討論／等待／停止／取消／阻礙不被轉成未授權實作；簡單任務保持低負擔。

**Blocked by:** H05A（真實接入與控制合格）。

**Status:** pending

規格：[任務合約與必要 hooks](../specs/task-harness-lifecycle.spec.md)。案例及上限：[H05](task-harness-lifecycle-05-desktop.plan.md)。

- [ ] 固定 C1、V1、V2、V5 的輸入、必要成果、禁止行為、turn／session 上限與證據；agent 工作副本不包含固定答案及維護者 checker。
- [ ] 重用已知單一 bug、三項 checker 判準、既有合約 fixture 與事件摘要；checker 相關變更時先重新驗證資格，不新建案例框架。
- [ ] C1 每個負例均無被禁止的產品變更或實作續作；討論／等待兩案從舊 execute 合約開始，agent 必須依最新要求成功保存 discuss／wait，而非由測試端預填正確授權。必要狀態保存不被誤判為產品修改。
- [ ] V1 的正常、衝突及逆序必要成果全部驗收；合約建立、成功保存與相依操作有可追溯順序。
- [ ] V2 不把必要缺口降為建議；正常補齊與 hook 補救分開記錄。未觀察到產品正向補救不冒充 C0 已合格。
- [ ] V5 由 agent 維護一份精簡合約，交付單一完整成果與相稱驗證；沒有無理由拆分、委派或重複核准要求。
- [ ] 保存固定產物與獨立判定，維持案例版本及歷史結果；模型 final／回合 completed 不代替驗收。

完成條件：C1、V1、V2、V5 各項直接證據皆成立。預置失敗／合約均標記為受控案例；未完成、失敗及未驗證不改成後續建議。來源若修正，按風險補回歸與 review；checker 修正重評固定產物，不自動重跑 agent。
