### 執行順序

1. 先核對 Desktop 是否能只在該測試專案載入指定 hook 命令。設定、候選副本與測試輸出均限測試目錄；不得改日常專案、全域設定、已啟用 plugin 版本或快取。若信任／載入必須越過此範圍，記錄確切接入缺口並停止，不繞過或改走 CLI 冒充 Desktop。
2. 接入資格探針與產品 handler 分開標示。產品的 host 資格保持 false，不能為了驗證而先宣告已合格。必要時使用僅位於測試目錄的 Python 標準函式庫探針，記錄事件白名單欄位並呼叫指定候選；不收集完整 prompt、私人對話或其他專案資料。
3. 首個真正使用者要求只做文字 canary：回覆固定文字後正常結束，不執行產品修改、網路工作、套件安裝或長時間操作。資格探針在第一次正常 Stop 前，以測試級 exclusive-create 收據占用唯一一次額度，再要求模型回覆另一固定文字並結束；後續 Stop 一律不要求續作。此探針只為查明宿主協定，不替代候選的合約／授權判斷。
4. 將實際 SessionStart、UserPromptSubmit、Stop 的 session_id、turn_id、stop_hook_active 與可歸屬的先後順序對帳；確認自動提示是否再次觸發 UserPromptSubmit、turn_id 是否改變、後續 Stop 如何標示。觀察缺失或結果不明先保留，不啟動第二個對話重跑。
5. 由 agent 整理輸入、輸出、候選指紋與實際結果；資格判定需引用直接事件證據。若宿主鏈路仍不夠辨識原使用者回合，保持未就緒，不改用文字前綴猜測。驗證結束移除測試專案內的接線，保留必要證據；不操作日常配置。

### 最小輸出與判準

- 每筆只需 event name、session/turn ID、stop_hook_active（事件有提供時）、接收序號、選用命令／候選指紋及輸出分類；缺值保留為缺失。
- 正常：事件可歸屬本候選／本對話；canary 確實延續一次後結束；後續事件沒有重獲額度。
- 未驗證：事件未送達、Python／信任／載入失敗、無法確認訊息來源或結束結果。程序或回合狀態不明不當成失敗重跑。
- 此次不驗收使用者原生 Stop、跨對話接手、完整任務生命週期及人工投入改善。即使接點探針成功，H05 仍須對原始完整 checklist 逐項補證，不能因只獲一次 trial 授權而縮減整體完成條件。

本節只是具體驗證契約，尚未建立測試專案、探針或對話，未執行任何新模型 trial。沒有新增 OS 隔離、watchdog 或背景監控需求。
