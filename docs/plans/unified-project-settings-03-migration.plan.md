# T03：設定移轉、衝突與修復

**What to build:** 以一次性移轉與規格化修復處理既有專案，資料不遺失。

**Blocked by:** T02

**Status:** done; migration, preservation and fault cases verified

依據：[實作規格](../specs/unified-project-settings.spec.md)。使用者已確認 T01–T08 拆分與依賴。

## 驗收條件

- [x] 提示後移轉；三項刪檔門檻全過才刪除舊設定，不留備份。
- [x] 衝突、寫入／驗證／讀回失敗及中斷時保留原檔並查明。已驗證部分完成狀態恢復；未強制中斷正在執行的移轉 OS 命令。
- [x] 既有產物位置不變；舊環境資格只留歷史；缺漏／重複／無效欄位不猜測。

## 證據要求

B、C 的逐項對帳、三門檻證據、負例與檔案／位置對照。

狀態更新只能依實際成果；調查、離線測試與真實行為驗收分別判定。

## 開發階段紀錄（後續結果見 T08）

已實作 harness 自帶的移轉／修復操作規格及觸發指向，涵蓋逐項對帳、保留完整檔名、三項刪檔門檻、未知資料與衝突保留、路徑邊界及中斷恢復。沒有新增日常依賴的 parser 或移轉腳本。

參照連結、文件讀回及 diff 檢查通過。兩個原生模型案例已完成並以產物獨立核對：成功移轉保留舊目錄與完整檔名、保存舊資格歷史、通過三門檻後刪除舊設定且不留備份；路徑衝突案例回報差異並保留新舊設定。兩例既有合約、JSONL 收據與其他檔案內容未變，原登入檔未變，模型回合正常完成；原始紀錄及來源指紋交由 T08 彙整。

完整 B／C 仍須涵蓋無效值、重複、寫入／讀回失敗及中斷恢復；目前結果不代表這些尚未執行的分支或整合候選已通過。

## T08 最終對帳

成功、衝突、無有效讀回及新檔已寫／舊檔仍在的恢復案例通過；最終候選另以真實 OS EPERM 寫入／刪除失敗、EACCES 讀回失敗驗證保留舊檔與歷史產物，不解除使用者禁止改變的旗標或權限、不留替代設定。讀回故障跨兩次 native invocation，恢復 fixture 明示預置部分完成狀態；未宣稱曾在移轉工具命令中強制 OS 中斷。
