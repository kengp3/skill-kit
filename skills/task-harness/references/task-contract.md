# 任務合約與標準 hooks 使用說明

本版以單一 Markdown 任務合約保存約定與恢復資訊，由主責 agent 維護。原生 tracker 只有在能保存完整合約、跨對話恢復及支援相同流程檢查時才能取代它；目前實作路徑是 Markdown，不假定宿主原生清單已符合條件。

## 使用方式

在任務開始時說「使用 `$task-harness` 完成這項任務」即可。agent 核對授權、建立並成功保存合約後推進，使用者不必手動維護狀態表。

- 同一任務後續回合與明確續作沿用原合約；新任務不自動繼承。
- 跨對話可說「使用 `$task-harness` 接續這份任務合約：`<合約路徑>`」。agent 先核對現況與原執行者，再保存接手資訊。
- 「先討論，不修改」只授權討論；正常收尾 hook 不得因此啟動實作。
- 使用者 Stop 後須有明確續作指示；不能保證 Stop 前最後一次保存已完成。

## 專案接入

專案設定依 [Task Harness 設定規格](project-settings.md) 由模型讀取，實際長期設定只存於已確認根目錄的 project-setting.md。缺失、舊格式或無效設定時，task-harness 提供該規格，交由 project-setting 初始化、移轉或修復，再讀回檢查。任務合約與技術收據位置只取自共用文件分類表。

核心流程不依賴 Python、runtime script 或外部輔助工具。標準 hooks 依[隨技能提供的接入規格](project-settings.md#codex-標準-hooks-接入)設定，宿主信任另行診斷；修復後仍不可用時，由主責模型使用同一合約主動執行檢查，不因此阻擋整個任務。不把設定寫入、格式讀回或離線 payload 當成真實 hook 執行證據。

使用者明確啟用任務後才能操作；安裝技能與設定成功不等於任務授權。完整候選保留技能及參照文件，標準 hooks 仍須按宿主能力接入，失效時由模型接手；具體宿主限制與模型接手狀態須如實回報。不要為接入自動安裝 runtime 或修改全域設定、其他專案。

## 唯一合約範本

將下列外層 Markdown 範例內容保存為合約目錄內的一個 `.md` 文件。外層四個反引號只為展示；實際文件從標題開始。固定標記間恰有一個 JSON code block，結構化狀態僅由它提供，由主責模型讀回核對；不要在另一檔或另一狀態表重複維護。

````markdown
# 任務合約：修正空輸入解析

<!-- task-harness-contract:v1 -->
```json
{
  "schema_version": 1,
  "task_id": "parser-empty-input",
  "project_root": "/absolute/project",
  "owner_session_id": null,
  "status": "pending",
  "objective": "空輸入得到約定結果，既有有效輸入維持原行為",
  "scope": ["修正解析流程與相稱回歸驗證", "不改外部 API"],
  "requirements": [
    {
      "id": "T1",
      "outcome": "空輸入符合需求，既有有效輸入回歸通過",
      "status": "pending",
      "depends_on": [],
      "evidence": []
    }
  ],
  "authorization": {
    "user_turn_id": null,
    "mode": "discuss",
    "basis": "尚未填入本回合實際授權；此範本不能據以開始實作"
  },
  "recovery": {
    "next_action": "核對需求與實際授權，再由主責 agent 保存綁定",
    "blockers": [],
    "unknown_operations": [],
    "cancellation_reason": ""
  }
}
```
<!-- /task-harness-contract -->

## 約定與驗收依據

補充需求來源、具體預期行為、必要驗證與證據定位。JSON 的 outcome 與 evidence 可指向此處，不另建進度權威來源。

## 恢復與變更依據

保留重要範圍變更依據、已完成但尚待核對的操作，以及接手所需資訊。只補充解釋，不在此維護另一份狀態或授權值。
````

保留範本的核心欄位。`task_id` 是本任務穩定的本地識別字；`owner_session_id` 與 `authorization.user_turn_id` 只填實際可觀測的宿主值，未取得時保留 `null`，並在授權依據與恢復資訊說明限制。`null` 本身不授予接手權，也不表示已有執行者已停止。主責可依目前真實對話與使用者要求進行模型主導流程，不為滿足舊 helper 的驗證而虛構宿主 ID。`scope`、`depends_on`、`evidence`、`blockers`、`unknown_operations` 都是字串陣列；無項目時用 `[]`。`basis`、`next_action`、`cancellation_reason` 是字串。

任務及成果狀態只有 `pending`、`in_progress`、`blocked`、`done`、`cancelled`。`authorization.mode` 為 `execute`、`discuss`、`wait` 或 `stop`，另記本回合授權依據；整體狀態不等於本回合授權。取消任務須在 `recovery.cancellation_reason` 留下依據；取消個別成果須在該項增加非空 `cancellation_reason`。取消不是驗收成功，全部取消不構成整體 `done`。

每個成果有穩定且唯一 ID。`depends_on` 僅指向存在的其他成果，不得自指或循環。小任務可只有 `T1`，驗證併入同一成果；只有具體必要的整合成果才另拆項目。`evidence` 應定位相關產物／檢查及其版本，agent 仍須判斷證據是否支持 outcome，不能只憑字串存在宣告通過。

由主責模型檢查固定標記、唯一狀態區塊、核心欄位、重複 keys、合法狀態與成果依賴；缺漏或歧義先核對同一份合約，不猜測授權。先讀已知合約；需要查找時，只在確認專案內依分類表縮小範圍，不掃描其他專案或按時間猜選。內容超出當前可完整核對的範圍時，說明缺口並定向查閱，不能截斷後當作完整狀態。選配 helper 可能有自身格式、大小或宿主 ID 限制；其拒絕不代表核心流程必須安裝或依賴它。

## 保存、綁定與恢復

開始產品操作前成功保存合約；在重要狀態轉換、接手與正常收尾更新並讀回，不為每次檢查記帳。一次保存可以同時包含前置驗收與接續資訊。若保存失敗或結果不明，核對同一份文件並修復，確認成功前暫停相依操作；不另建替代合約、不盲目重做產品修改。

同一對話同時只主責一個未結束任務。切換前先保存原任務交接資訊並解除可觀測的 `owner_session_id`，不複製或取消。宿主未提供 ID 時，在恢復資訊說明本次主責與交接依據，保留宿主欄位為 `null`；不要把本地說明冒充宿主身分。跨對話接手先核對原執行狀態與實際產物，成功保存新的主責身分或有依據的交接說明後才推進。找不到已知合約時只在確認專案內查找；多份綁定或歧義需核對，不按時間猜選。這是單一主責協議，不宣稱提供跨程序原子鎖。

續作保留仍有效成果，只重驗受影響部分。`unknown_operations` 先查原結果／實際副作用，不能當失敗直接重跑；Stop／中斷後從最近成功保存的內容核對，不假設最後保存存在。範圍改變更新同一合約並保留必要依據；新目標另建任務時不繼承舊授權。

## Hooks、模型接手與技術收據

[主流程](../SKILL.md#check-the-same-contract-at-workflow-boundaries) 定義四個共用檢查時點。hooks 正常時提供觸發提醒；不可用時由主責模型主動執行相同檢查，不另建任務或設定副本。

| 事件 | 標準接入的作用與實際能力界線 |
| --- | --- |
| `SessionStart` | 提醒讀取已確認專案設定及現有合約，核對恢復與授權；靜態命令不會自行查檔、綁定或提供動態 session 身分 |
| `UserPromptSubmit` | 提醒主責核對最新使用者要求並保存授權；靜態命令不會解析輸入、提供回合身分或更新合約 |
| `Stop` | 主責在正常結束前主動核對完成條件；只有宿主實際支援且已有證據時才能聲稱具條件續作。固定 `{}` 是被動合法回應，沒有條件補救或強制完成能力 |

接入先讀實際載入定義、信任與事件結果，分別回報「設定已寫入」「宿主已載入／信任」「事件已觸發」「成果已驗收」。只寫入定義或重播靜態輸出不構成模型已收到提醒的證據。修復限原授權；設定變更交給 project-setting，完成後重查。若仍不可用，在同一合約的恢復資訊記錄可觀測的缺口與模型接手，不要求安裝 runtime、外部服務或手動監看。

宿主若提供可驗證的有界收尾補救，最多同一使用者工作回合一次，且保持原授權與實際額度；識別已是續作、`stop_hook_active=true` 或無法可靠辨識原回合時，不再自動延續。討論／等待／停止／取消／實際受阻時，不以 hook 產生新實作授權；未知操作只查核結果，不能重送。單靠固定輸出無法提供此條件判斷，不得改成無條件 block 以冒充強制力。

恢復 hook 或收到重複提醒時，先核對同一合約、實際副作用及已啟動 agent；不重做已完成操作或重複派工。狀態不明先查明，只有成果或條件改變時重驗受影響項目。恢復本身不重置任務、授權或補救次數。

技術收據只能記錄有直接證據的真實 hook 操作，位置取自文件分類表；沒有實際事件就不建立假收據。模型主動檢查寫入任務合約，不冒充宿主事件或原子去重保證。若某個可選接入確實產生去重收據，保留既有收據與已知操作結果，不能刪除紀錄爭取重試；保存失敗按未知結果核對，不掩蓋錯誤或盲目重送。

## 驗收限制

離線檢查可驗證格式、分支、去重與封裝內容；實際執行環境的載入／信任、事件與補救鏈，以及真實 agent 對任務合約與成果的遵循，需各自取得直接證據。原生回合結束不等於整體任務完成，未驗證就明示未合格。

保存執行版本、候選指紋、模型／推理設定、實際載入來源與相關設定；只有核心版本、協定及相關設定等效有依據時才重用證據，差異按影響補驗，不為不同 UI 重做全套或宣稱未測環境已通過。不要求使用者計時、人工觀察或維護報表。評測、grader、OS 隔離與 watchdog 不屬於日常任務路徑。
