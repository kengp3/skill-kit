# 模型選擇與派工

主責模型以本規則判讀設定並使用宿主原生 agent 能力派工；不需要模型解析器、外部 dispatcher、CLI 或 runtime script。設定語法、欄位與有效性以 [專案設定規格](project-settings.md) 為準，任務狀態仍在 [同一份任務合約](task-contract.md)。

## 每次派工前

1. 核對本次使用者指示、現有任務覆寫、準備執行的成果、agent 角色及階段。使用已讀且仍有效的專案設定；設定剛變更時先重讀。階段或角色不明而會改變模型選擇時，先釐清該工作，不任意取一個有設定的名稱。
2. 按下表找到第一份適用設定，保留其候選清單及選擇依據。沒有設定與格式有效但目前不可用分開處理：前者往下找，後者進入該清單的回退流程。
3. 解析首選及其推理強度，核對宿主可表達的模型、強度與角色設定。只有宿主提供的能力可用於派工；固定角色模型、工具參數限制與原生優先序仍有效。
4. 需要其他模型的工作交由指定模型的原生 agent 執行；同模型且無委派效益的小工作可由主責執行。提供範圍、成果、驗收與實際限制，成功啟動後保存真實 handle、請求設定與可觀測結果，再繼續協調。
5. 核對宿主實際採用結果與原要求。若被角色固定設定或宿主規則改變，記錄差異並按不可用／回退規則處理，不能把未採用的指定宣稱為成功。回報後核對成果與證據，更新原成果，不另建模型狀態表。

| 優先序 | 適用來源 | 判讀方式 |
| --- | --- | --- |
| 1 | 本次使用者明確指定 | 只套用其明確範圍；在任務合約保存供同任務恢復 |
| 2 | 個別任務設定 | 合約內仍有效、適用此項工作的單次覆寫 |
| 3 | agent 角色設定 | 專案 `model.role.<完整角色名稱>` |
| 4 | 任務階段設定 | 專案 `model.stage.<完整階段名稱>` |
| 5 | 專案預設 | 專案 `model.default` |
| 6 | 沿用主責 | 前五項皆未設定時，繼承主責當前模型及推理強度 |

低優先序設定不是額外替代清單。同一層存在互相衝突且無法由最新明確指示解決的適用設定時，回報衝突，不猜選。任務、階段及角色名稱與實際工作對應，不因某列存在就自動新增工作。

## 原生派工介面的模型綁定

- 宿主派工介面接受模型與強度參數時，使用其原生參數並核對生效結果。介面沒有這些參數時，先檢查既有原生角色設定，選擇同時符合本次職責與模型／強度要求的角色；不能僅因角色名稱相近就假定模型相同。
- 宿主已驗證支援以本地角色設定指定模型，但沒有合適角色時，在原授權涵蓋本地設定操作的前提下，先讀取該宿主目前的角色格式與載入方式，再把目標模型、強度、角色職責及規格提供給 project-setting，建立或修正最小的專案角色設定。保留其他角色，讀回並確認宿主實際載入後，才使用該角色派工；不猜測檔名、TOML 欄位或自行改動全域設定。
- 缺少逐次模型參數不等於無法建立 agent，也不等於已證明該模型不可用。若原生角色路徑仍不能滿足要求，記錄實際限制並按回退／接手規則處理；不能默默以不同模型啟動，或另建必要外部派工器。角色配置是執行接線，不取代 project-setting.md 中的專案模型規則或合約中的單次指定。

## 階段與主責模型

| 預設階段 | 工作內容 |
| --- | --- |
| 規劃 | 需求釐清、方案研究及任務拆解 |
| 執行 | 實作或產出任務成果 |
| 驗證 | 執行檢查，核對成果與驗收證據 |
| 審查 | 評估品質、風險與遺漏 |

可使用專案自訂階段，例如「設計」或「研究」；對應完整名稱，不改寫成另一個預設名稱。階段只供工作及模型設定對應，不強制任務依表順序走完所有階段，也不要求每個階段建立 agent。未設定的自訂階段依同一優先序處理。

主責維持使用者在對話中選定的模型，階段設定不會自行切換主責。使用者手動切換對話模型後，後續真正繼承主責的工作及派工跟隨最新模型與推理強度；已有有效任務、角色、階段或專案設定的工作仍依那些設定。已啟動 agent 維持原模型與強度，不重啟或重派。主責當前選擇不可觀測時，記為未知，利用宿主原生繼承而非虛構模型名稱。

「切換對話模型」不等於「所有 agent 改用該模型」。只有使用者明確指示相應範圍時才建立該項任務覆寫。

## 候選與推理強度

候選格式為 `[模型A;high, 模型B;medium]`，第一項是首選，其後依序替代。可用 `[模型A;high, 模型B]` 省略部分強度，或 `[模型A, 模型B]` 全部省略。逗號分隔候選、分號連接模型與強度，分隔符周圍空白不影響結果；範例不是預綁的模型推薦。

- 明確指定模型但未填強度，使用宿主對該模型的預設；不要把主責強度填入空白。
- 完全繼承主責時，模型及強度一起繼承。
- 替代候選採自己的強度，不複製上一模型的強度。
- 格式錯誤依專案設定規格交給 project-setting；格式正確但模型不可用或強度不支援，交給執行回退，不改寫原設定。

## 合約中的最小紀錄

模型資料與原任務合約一起保存，不建立專用檔案或複製整份專案設定。沿用原 JSON 區塊與既有必填欄位；需要單次指定或實際派工紀錄時，可增加下列可選頂層欄位。沒有相關資料時省略，不為每個工具操作建立一筆。

| 可選欄位 | 每筆必要內容 | 用途 |
| --- | --- | --- |
| `model_overrides` | `applies_to`：本任務／既有成果及明確角色或階段範圍；`candidates`：原指定的候選清單；`basis`：實際指示依據 | 保存本次指定及適用範圍，不成為專案長期設定 |
| `model_runs` | `requirement_id`：既有成果 ID；`executor`：主責或實際 agent；`handle`：真實 handle，無則 null；`selection_source`：採用的優先序來源；`requested`：模型與強度要求；`observed`：可查證的實際結果及其證據，未知值為 null 並附原因 | 保留重要派工、替代或主責接手的結果，供恢復與驗收對帳 |

`model_overrides` 與 `model_runs` 均為紀錄陣列。`applies_to` 須明確引用目前任務、既有成果或實際使用的角色／階段，不能含糊寫成永遠適用。`requested` 與 `observed` 各包含 `model`、`reasoning_effort`；要求繼承時記明繼承來源，未知實際值仍為 null。`observed` 另保留 `basis` 或 `evidence` 定位宿主回應；模型自行宣稱的身分不構成該證據。

此處只定義模型補充資料，不改寫成果狀態、授權或依賴的既有權威欄位。紀錄模型不等於成果通過；agent 回報仍須驗收。處於啟動結果不明的紀錄須連回原本的恢復／未知操作欄位，不能因只有 requested 就視為已派工或自行重派。

單次指定在恢復同一任務時仍有效，新任務不沿用。使用者明確要求「設為專案預設」時，才依專案設定規格委派 project-setting 更新長期設定並讀回；成功替代或實際使用某模型不構成該授權。

## 不可用、結果不明與回退

先辨識宿主的實際回應，再決定下一步。格式錯誤交給設定修復；格式正確不表示帳號目前可用。認證、連線或共用額度問題不能冒充「此模型不支援」，也不能靠輪流派出更多 agent 來診斷。保留原始原因，依影響範圍修復或回報；只有已知沒有啟動，或已查明原操作結果，才能安全改派。

| 觀測情況 | 處理 |
| --- | --- |
| 已知候選模型不可用，且未啟動工作 | 記錄原因，前進到同一候選清單的下一個模型 |
| 模型可用、指定強度不支援 | 保留該模型，改用宿主對該模型的預設強度並記錄修正；仍無法啟動才前進下一候選 |
| 使用者明確要求強度不可變更 | 維持限制；只嘗試符合限制的後續候選，不能自行採宿主預設或降低要求 |
| 認證、連線或共用額度問題 | 先核對實際問題及原啟動狀態；在原授權內處理，不把共通故障當成每個模型各失敗一次 |
| 回應逾時、斷線或啟動結果不明 | 將真實 handle／操作依據連回合約未知操作，查原 agent、宿主結果與產物；查明前不另派同一工作，也不把「等不到」當成未執行 |

同一次選擇流程，按原順序處理首選與替代候選，不把較低優先序的角色或階段設定串入替代鏈。以模型識別字去重，保留第一次候選的強度；後面同模型即使附不同強度也不另試。上表允許的同模型強度修正是一次受控修正，不重頭跑候選清單、不重派已啟動工作；修正前也須確認原要求未成功啟動。

候選清單耗盡後，自動執行一次末段預設回退，不要求填寫 `default`。清單若明列 `default`，只在最後一項解決相同的回退，不增加第二次回退：

1. 有專案預設時使用專案預設候選清單，沿用各候選自己的強度。若它本來就是此次採用的清單，不重新進入自身；只處理尚未嘗試的模型。
2. 沒有專案預設時，沿用主責在回退當下的模型與強度。宿主可原生繼承但不能回報識別字時，記錄繼承依據及未核實限制，不杜撰一個模型來做去重；若不能排除與已嘗試模型重複，先查明原生設定，查不明時保留該回退缺口，不盲目重派同一工作。
3. 已嘗試的模型跳過；專案預設中的 `default` 不遞迴進入自身。有專案預設但其中模型也不可用時，不額外擅加主責模型作最後候選。

包含預設回退仍沒有可用候選時，將該項工作保留未完成並詢問所需決定，繼續其他不受影響的工作。明確模型／強度限制依使用者指定的範圍套用：例如「所有 agent 只能 high」不能改派 medium；只限制某一候選的強度，則不擴大成所有候選皆受限。任何回退都不改寫原任務指定或專案設定。每次重要替換將原要求、原因、候選順序、強度修正與實際執行者／可觀測模型記入原合約的 `model_runs`；實際模型或強度不可觀測時保持 null，不能把請求值填成觀測值。

## 無法建立子 agent

缺少逐次模型參數時，先走前述原生角色綁定，不能直接判為完全無法派工。若宿主確實無子 agent 能力，或在原授權內診斷及嘗試修復後仍無法建立子 agent，由主責按原任務分工循序接手，沿用同一份任務合約、檢查時點與驗收規則，不要求使用者另行同意一般協作模式，也不引入必要外部派工工具。

若失敗明確發生在啟動之前，已核對沒有成功 handle 或執行中的原 agent，且原因是歷史／上下文無法載入，可在宿主已支援的新上下文模式中提供自足的任務輸入再試。保留同一成果、模型與強度要求，補足需求、檔案位置、授權及驗收依據，並記錄這次接線修復；不硬編碼錯誤字串、不假定所有上下文都可丟棄。這不是改用下一模型，也不構成重試未知啟動的理由；若工作必須保留原上下文而無法完整交付，保留該限制並按接手規則處理。

接手紀錄的執行者是主責，實際模型是主責當前可查證的模型；不能宣稱已切換成原本請求的候選模型。已有 agent／啟動結果不明時，仍先核對其狀態，不能用主責接手重做同一副作用。這個分支處理的是無法建立子 agent；仍可派工但指定模型候選全數不可用時，保持前述「受影響工作暫停並詢問」的結果，不能藉接手略過模型限制。

若任務明確要求獨立 agent 審查，主責可作必要的自我檢查，但獨立審查條件保持未完成並回報具體缺口；主責自行換一個角色名稱或重新閱讀，不構成獨立審查。繼續其他已就緒工作，不刪除該條件、不以自我核准宣告整個任務完成。

## 回退與接手的驗收對照

以下只定義預期結果；需用實際 agent 與宿主／產物證據驗收，不能把示意的「不可用」當成真實錯誤。

| 輸入與觀測 | 預期結果 |
| --- | --- |
| 角色清單為 A、B、A；A 已知不可用，B 可用；階段另設 C | 只按 A、B 前進，不再次嘗試 A，也不自動改用 C |
| 首選清單用盡，專案預設為 B、D，B 已試過 | 只處理尚未嘗試的 D；預設失敗不額外加入主責 |
| 無專案預設，首選清單用盡 | 末段回退沿用主責當前模型及強度，既有同模型不重試 |
| A 的 high 不支援，但 A 宿主預設可用 | 保留 A、記錄強度修正；原 high 未成功啟動才採修正，不派出兩份工作 |
| A 的 high 不支援且強度明確不可變更 | 不採預設強度；只有符合限制的候選可繼續，沒有可用項則保留缺口 |
| 啟動 A 逾時，尚未確認是否執行 | 查原 handle 與結果，未查明前不派 B 或由主責重做 |
| 無子 agent 能力；任務含一般成果與獨立審查 | 主責完成可執行成果，獨立審查保持未完成，不宣稱整體通過 |

## 正常選擇的驗收對照

使用實際專案設定、同一合約及原生 agent 結果驗收；文字示意只能建立預期，不能宣稱已完成派工。

| 輸入 | 預期選擇 |
| --- | --- |
| 本次明確指定 A；任務 B、角色 C、階段 D、專案 E 均有設定 | 採 A，保存指示範圍與依據；其他設定不成為自動替代鏈 |
| 本次無指定；任務 B、角色 C、階段 D、專案 E 均有設定 | 採 B；恢復同一任務仍適用，新任務不承接 B |
| 本次與任務無指定；角色 C、階段 D、專案 E 有設定 | 採 C，角色名稱須與本次派工一致 |
| 僅自訂「研究」階段 D 與專案 E 有設定 | 研究工作採 D，不強制另走其他四階段 |
| 僅專案 E 有設定 | 採 E；不因對話模型手動切換而覆蓋它 |
| 所有來源皆無設定 | 沿用主責當前模型及強度；手動切換只影響後續繼承，已有 agent 不變 |

驗收比對設定要求、宿主解析值與實際執行證據；只取得解析值時明確標「宿主解析值」，只取得請求值時實際結果仍未知。固定角色設定妨礙指定時須顯示差異，不把另一模型的成果算成指定模型已生效。
